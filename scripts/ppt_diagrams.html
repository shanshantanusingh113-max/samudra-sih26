The extensibility seam. Four providers, four adapter classes, one interface - and the fourth shares no convention with the others: depth not pressure, one row per level, no quality flags. The renderer, the API and the UI have never heard of ERDDAP. Everything served on the right comes off the Grid and never the Volume.

How it is built

Ingest → reconcile → encode → render → compare

01 INGEST
Read the archives xarray reads CF-compliant NetCDF over ERDDAP; a parser reconstitutes Argo casts from flat CSV.
02 RECONCILE
Depth Warp 24 uneven levels → an even GPU axis that gives the top 300 m half the resolution, not 15%.
03 ENCODE
4 bytes a voxel Value, coverage (where ocean truly is), gradient (where it is changing), spare.
04 RENDER
Ray-march in WebGL2 Front-to-back compositing with an editable transfer function and isosurface hits.
05 COMPARE
Collocate Model interpolated to the float's own position, depth and time. Residuals, signed.

Feasibility & risk

Every risk below was hit during the build - and resolved

RiskWhat actually happenedResolutionState
No access to INCOIS data Assumed unavailable; HYCOM was the fallback plan INCOIS runs a public ERDDAP. We use their own product, current to 30 Jul 2026 SOLVED
Upstream server unreachable HYCOM and NOAA CoastWatch time out from our network Data baked into the build; the demo makes zero network calls SOLVED
Weak GPU in the demo room Target is Intel UHD, 2 GB shared VRAM Adaptive ray steps, byte-quantised volumes, textures freed on swap SOLVED
Bad sensors in real data A live float reports 20 PSU - impossible in open ocean Per-channel QC; the cast keeps its good temperature SOLVED
Rendering that misleads Interpolating a no-data value paints fake upwelling along coasts Separate coverage channel; land can never fabricate a temperature SOLVED
Scaling to full archive 813 analysis steps exist; 12 are baked Same pipeline, run longer. Volumes are 159 KB each DESIGNED
