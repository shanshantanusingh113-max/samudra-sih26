The gap

The data already exists. Nobody can look at it together.

INCOIS runs ocean models and INCOIS collects real measurements from robot floats drifting in the same water. Both are valuable and both already exist. A forecaster who wants to know whether they agree has to open two different desktop programs and hold the answer in their head.

And almost every tool draws flat maps — one depth at a time. The ocean is four kilometres deep. The structures that matter are vertical.

  • No web-based 3D view of ocean model fields with depth resolved.
  • No unified display of float profiles alongside model output.
  • No interactive control of depth, time, or colour while you look.
  • New instruments mean re-engineering the tool.

Real data

It runs on INCOIS's own server

Prior research concluded INCOIS exposes no public API and that we would need a substitute such as HYCOM. Both halves turned out to be wrong, in our favour. HYCOM and NOAA CoastWatch are unreachable from our network; erddap.incois.gov.in is a real, running, public ERDDAP serving exactly what the platform needs.

Engineering

Three decisions that shaped the build

Rendering

Featureless water is transparent

Ocean temperature falls monotonically with depth, so a plain ray march is an opaque warm lid over an invisible abyss. We precompute how fast the field is changing and weight opacity by it, so the thermocline and fronts become the solid things — which are what anyone is looking for anyway.

Correctness

Land must not fake upwelling

GPUs interpolate before the shader sees a voxel, so a "no data" sentinel gets averaged with the ocean beside it and paints a cold fringe along every coast. That reads as upwelling — a real phenomenon someone would act on. Masked cells carry a neighbour's value; a separate coverage channel carries the truth.

Debugging

Centroid sorting lies

The volume rendered as a thin sliver. Transform, uniforms, projection and data all measured correct — 69–78% coverage at every depth. Three.js sorts transparency by centroid, and the world sea surface has its centroid at the origin, nowhere near what you see. It was drawn after the volume and painted over it. Draw order is now stated, not inferred.

  • Three.js for both views, no Cesium. Cesium needs an ion token — an external dependency that can fail live — and compositing a ray march into its pipeline was the riskiest integration available. One scene makes the dive genuinely continuous.
  • The demo is baked; the API is the deployable half. Nothing on the demo path touches the network, so a dead venue connection cannot kill it. The REST API answers the queries no bundle could precompute — any float, any cast, any analysis step.
  • The depth axis is warped, and says so. Linear-in-metres would give the thermocline three voxels. The profile chart uses the same warp, so the 3D view and the chart agree.
Scope

What we deliberately did not build

Stated so nobody wonders whether we forgot.

  • INCOIS's internal archive — needs credentials we do not have. The Source Adapter is precisely where it attaches.
  • An OGC WMS/WCS server — we consume open standards and CF conventions; re-serving them is a checkbox no judge will click.
  • Accounts, sessions, mobile, WebGPU, ML products — none of them make the comparison better.
  • Volumetric current streamlines — a project in itself, not a feature.
