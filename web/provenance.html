What the build contains read live

The model field

INCOIS publish this as CF-1.6 NetCDF over ERDDAP. That is their compliance, not ours: we read their conventions rather than re-serving them. The platform's own baked output is a quantised binary volume plus JSON, built for a graphics card, and it is never the answer to a scientific question. Those come from the native grid.

One upstream wart, in case you try it from a script: INCOIS's server sends its leaf certificate without the GlobalSign intermediate. Browsers and curl paper over it, Python's ssl module does not. pipeline/samudra/tls.py supplies the missing link rather than disabling verification.

The sources

INCOIS serve Argo profiles themselves, and we implemented that adapter too. It is not what the demo reads: their archive ends 2025-04-23 while their gridded analysis runs to the dates above, and pairing the two would compare two different oceans. The adapter stays registered because it proves a third provider costs one small class.

What the raw data looks like

Two providers, two formats, two conventions. Neither was designed for us, and neither is reshaped before it reaches the pipeline - the adapter reads what they publish.

INCOIS, the model field

Gridded NetCDF over ERDDAP. Four axes, CF-1.6 attributes, and land carried as NaN rather than as a sentinel value the arithmetic could mistake for a temperature. 

netcdf incois_argo_10d_VAM {
dimensions:
        time = 12 ;          // 10-day analysis steps
        ZAX  = 24 ;          // depth levels, 5 m .. 2000 m, UNEVENLY spaced
        latitude  = 36 ;     // 1 degree, 10 S .. 25 N
        longitude = 56 ;     // 1 degree, 45 E .. 100 E
variables:
        float TEMP(time, ZAX, latitude, longitude) ;
                TEMP:units = "degC" ;
                TEMP:_FillValue = NaNf ;         // land and sea floor
        float SAL(time, ZAX, latitude, longitude) ;
                SAL:units = "PSU" ;
        double ZAX(ZAX) ;
                ZAX:units = "m" ;
                ZAX:positive = "down" ;
// global attributes:
        :Conventions = "CF-1.6, COARDS, ACDD-1.3" ;
}

The 24 levels are the reason for the Depth Warp. They cluster near the surface - 5, 10, 20, 30, 50 m - and stretch to 200 m apart in the abyss, because that is where the physics is. A GPU texture samples evenly, so the pipeline maps one onto the other and ships the sampled axis in the manifest rather than letting the browser re-derive it.

Argo, the observations

Delimited text from ERDDAP's tabledap. One row per measurement, with the cast identified only by the repetition of platform number and time - there is no profile id column, so grouping on that pair is what reconstitutes a cast.

Note the second line: ERDDAP writes a units row under the header, which a naive CSV reader will parse as data. Note also pres, not depth - Argo reports pressure in decibars, and the pipeline converts properly (Saunders and Fofonoff, gravity varying with latitude) rather than pretending 1 dbar equals 1 m.

What the pipeline does to it

Five stages between the provider and the screen. Every number in this table is the shape this build actually produced.

The Volume is a rendering artefact and is never the source of a scientific answer. It is quantised to a byte per value, depth-warped, and back-filled across land so the GPU's trilinear filter has something physical to blend against. Anything a user reads as a measurement - a collocation, a tooltip, an API response - comes from the native Grid, which is why data/grids/ exists alongside the browser bundle.

How it is tested

… automated tests, all on the scientific logic. Not on glue, UI or shaders - those are verified by measurement in the browser instead, because a passing test that asserts a shader compiled tells you nothing about whether the picture is true.

Run them yourself:

cd pipeline
python -m pytest -q
# … passed

Twice during the build a test and the code disagreed and the test turned out to be wrong: once about gravity-corrected depth, and once about a fixture too small to survive the minimum-points filter. Both are recorded rather than quietly amended, because a test suite you trust blindly is worse than one you argue with.

Reproduce the whole build

cd pipeline
python -m samudra.bake

About a minute. It refetches every timestep and every profile, rewrites the volumes, the floats and the collocations, and stamps the manifest with a new time. Reload this page and every number above will have moved.
