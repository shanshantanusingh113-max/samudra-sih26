The gap

The data already exists. Nobody can look at it together.

INCOIS runs ocean models, and INCOIS collects real measurements from robot floats drifting in the same water. Both are valuable and both already exist. A forecaster who wants to know whether they agree has to open two different desktop programs and hold the answer in their head.

Today

Two windows, flat maps

Model output in one program, float measurements in another, and almost every tool draws one depth at a time. The ocean is four kilometres deep and the structures that matter are vertical.

Today

No answer to "is it right?"

A model has a value everywhere, whether or not anyone measured there. Nothing puts the prediction and the measurement on the same axes and sizes the disagreement.

Here

One block of water, both things in it

The model is a solid, see-through 3D volume you fly inside. The floats are in it, where they actually were. Click one and you get the comparison, quantified.

Here

And it says where nobody looked

One variable is not the model at all: it is the evidence behind it, counting the float casts near every point. Where that is empty, the platform says so instead of colouring it in.

How it works

Four steps, and nothing between you and the data.

Everything the demo needs is baked into the build, so it runs with the network cable pulled out. A dead venue connection cannot kill it.

01

Read the real thing

INCOIS's own gridded analysis over their public ERDDAP, and the Argo float profiles measured in the same water from the global data centre. Nine independent sources, each behind one small adapter, so a new instrument is a class rather than a rewrite.

02

Do the science once, in Python

Resample the depth levels, reject implausible values channel by channel, work out density with TEOS-10, find the anomalies, compute the hazard fields, and collocate every float cast against the model at that exact place and date. All of it tested.

03

Render it on your GPU

The volume is ray-marched in WebGL2, in one scene that morphs between a globe and a block of water. Sheets, drapes and moving dots handle the variables that are not a volume, because drawing a depth as a body of water would be drawing the wrong thing.

04

Answer questions from the grid, never from the picture

Every number you read comes from the model's own full-precision grid, not from the rendered block, which is quantised and depth-warped for the GPU's benefit. That distinction is the difference between a visualisation and an instrument.

For everyone, not just forecasters

The problem statement asks for a science communication tool. So there are two doors.

It names school and college students, the general public at awareness campaigns, and policymakers, and three settings: outreach events, exhibitions and e-learning. Fifteen variables in five groups is the right toolkit for a forecaster and the wrong first minute for any of those. So the same platform has a second way in, and the console gained nothing.

Students

Explore by question

Eight questions in plain words. Press one and the whole scene sets itself up: the variable, the date, the way the water is drawn, the camera. Every question carries the caveat its simplification costs, beside the answer and never after it.

Exhibitions

Kiosk mode

Panels hidden, type at reading-across-a-room size, the questions on a loop, and a reset sixty seconds after the last visitor leaves. Press Escape and the full console comes straight back.

E-learning

Copy this view

One button writes whatever is on screen into a link: the variable, the date, the depth, the pin, the section line. A teacher's worksheet is six links, and that is e-learning without an e-learning platform.

Anyone

Show me around

A guided walk in six chapters and twenty-one steps that visits every control the platform explains, opening each one's own explanation as it goes. Useful to a school class and to the person presenting it.

Evidence

Every number on this page is read from the build it describes.

Not typed in. The figures below are fetched from the same files the platform draws, so this page cannot quietly go stale while the data moves underneath it.

… Instruments compared

Every one with a profile the model can be held against, at the depths it actually reached.

How far the analysis sits from what the instruments measured, across the whole basin.

… Against moored buoys, degC

The honest number. INCOIS assimilate Argo, so a float is largely the model agreeing with itself.

Root-mean-square, so a big gap at one depth counts for more than the average gap does. Half the instruments sit under this and half above.

A model has a value everywhere whether or not anyone measured there. This platform draws that distinction rather than hiding it, and the number it is least comfortable with is the one it prints largest.

  • 377 automated tests over the science: the depth warp, the volume encoding, grid interpolation, collocation, the Argo parser, every derived variable, and the standards endpoints.
  • Thirteen browser probes that drive the built application and measure what actually reaches the screen, because every bad bug in this project looked like a shader bug and was not. One of them measures this page: no picture it names is missing, no request leaves the build, and the headline clears its contrast floor in both themes.
  • Two modules implemented twice on purpose, in Python and in the browser, and both copies measured against each other so the demo works with the network unplugged.
  • Nothing is smoothed over the gaps. Where the atlas has no normal the field is blank rather than zero, and where no cast reached the water the panel says so.
How it is built

Boring technology, used carefully.

Front end

TypeScript, React and Three.js on WebGL2. One scene renders both the globe and the volume and morphs between them, so there is no second viewer to keep in step.

Pipeline

Python with xarray and NumPy. Every source sits behind one adapter interface, and the scientific truth lives in one grid class that nothing else may go around.

API

FastAPI, serving REST plus OPeNDAP, CF-1.8 NetCDF and OGC WMS from the native analysis grids. It also accepts a NetCDF file a visitor drops in, and stores nothing.

Deployment

A static bundle. Push to the repository and it publishes. The demo path makes zero network calls, fonts included, so it survives a dead venue connection.

Open it and fly into the water.

No install, no account, no plugin. It runs entirely in your browser on real INCOIS data.
